# Model benchmark

The versioned 20-question suite measures how well inexpensive OpenRouter models use Minecraft Assistant's real prompt and tool contracts. Tool execution is fixture-backed, so a run needs OpenRouter but does not launch Minecraft or contact Minecraft Wiki.

Run the complete suite:

```sh
OPENROUTER_API_KEY=... ./gradlew :fabric:runModelBenchmark
```

Run selected models or questions:

```sh
OPENROUTER_API_KEY=... ./gradlew :fabric:runModelBenchmark \
  --args='run --models=openai/gpt-5.6-luna@high --questions=production-torches,quantity-stairs'
```

A bare model ID selects every configured reasoning variant for that model. Add `@low` or `@high`
to select one variant. The full baseline compares Luna, Sol, Claude Haiku 4.5, and Claude Opus 5 at
both low and high reasoning, plus the other lower-cost models listed in the suite file.

Resume an interrupted run without overwriting completed cases:

```sh
OPENROUTER_API_KEY=... ./gradlew :fabric:runModelBenchmark \
  --args='run --resume=benchmark-results/<timestamp> --budget=5.00'
```

The runner first checks OpenRouter's live catalog for each exact model ID, tool support,
`reasoning_effort`, and current list pricing. It stops before starting another model if the projected
total would exceed the budget. The default is $2 and the hard safety ceiling is $5.

Runs are written to the gitignored `benchmark-results/<timestamp>/` directory. `raw-results.json` contains the complete transcripts and provider measurements. `review.json` uses anonymous candidate labels and is the file a reviewer scores. It deliberately contains no model IDs.

After every case has a correctness score from 0–2, tool/context score from 0–2, chat-quality score from 0–1, and a short note for deductions, generate the report:

```sh
./gradlew :fabric:runModelBenchmark \
  --args='report benchmark-results/<timestamp>'
```

The report command validates the review, reveals the model mapping, and creates `summary.json` and `summary.md`. Published README results are a dated snapshot, not a permanent claim: OpenRouter routing, prices, and model behavior can change.

The versioned suite covers six factual Wiki questions, five native recipe/workstation guides,
production chains, deterministic quantity planning, route comparison, three conversation follow-ups,
and a strategy question that should remain text-only. Each case is worth five points:

- correctness: 0–2;
- tool and conversation behavior: 0–2; and
- compact Minecraft-chat quality: 0–1.

Failures score zero. Quantity answers are judged on the model's decision and semantic tool arguments,
because verified totals are generated by Java rather than authored by the model. The reviewer checks
Minecraft claims against the fixture expectations and Minecraft Wiki as needed, records a reason for
every deduction, and does not use a second model-as-judge request.

Every run retains the model catalog/pricing snapshot, seeded histories, tool calls and fixture
results, provider turns, usage, latency, errors, and actual OpenRouter cost. “Prompts per dollar” is
`20 / total suite cost`; one prompt includes every provider turn needed to answer one player question.

Secrets are read only from `OPENROUTER_API_KEY` (or the existing development alias `MINECRAFT_ASSISTANT_OPENROUTER_API_KEY`) and are never written to benchmark output.
